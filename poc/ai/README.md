# PoC #4 — AI เขียนโค้ดด้วยเฟรมเวิร์กของเราได้ถูกและปลอดภัยแค่ไหน

คำถาม:
1. AI ที่ไม่เคยเห็นเฟรมเวิร์กนี้มาก่อน เรียนรู้จากเอกสารหน้าเดียวแล้วเขียนได้ถูกไหม
2. โค้ดที่ AI เขียนด้วยเฟรมเวิร์กของเรา ปลอดภัยกว่าโค้ดที่เขียนด้วย Hono หรือเปล่า
3. build check จับ route ที่ลืมใส่ auth หรือ schema ได้ครบไหม

## สรุปผล

| คำถาม | ผล |
|---|---|
| AI เรียนรู้เฟรมเวิร์กใหม่จากเอกสารได้ไหม | **ได้เต็มที่** ทั้ง 3 รุ่นผ่าน hidden test 100% ทุกข้อ ทั้งสองรอบ |
| ปลอดภัยกว่า Hono ไหม | **ต่างกันน้อยมาก** รอบ 1: 61/61 เทียบ 60/61, รอบ 2: 50/50 ทั้งคู่ |
| โค้ดสั้นกว่าไหม | **สั้นกว่า 1.4–3.3 เท่า** (เฉลี่ยราว 2.3 เท่า) |
| build check จับการลืม auth/schema ได้ไหม | **100%** (324/324) ส่วนการ "ตั้งใจ" เปลี่ยนเป็น public ตรวจจับได้ 36/45 |

**ข้อสรุปตรงๆ:** สมมติฐานว่า "AI เขียนด้วยเฟรมเวิร์กเราแล้วปลอดภัยกว่าอย่างมีนัยสำคัญ" **ยังไม่ได้รับการยืนยัน** ในการทดสอบนี้ เพราะ AI รุ่นปัจจุบันเขียน API ขนาดเล็กได้ปลอดภัยดีอยู่แล้วทั้งสองเฟรมเวิร์ก ส่วนที่พิสูจน์ได้ชัดคือ AI เรียนรู้เฟรมเวิร์กใหม่ได้ทันทีจากเอกสาร และเขียนโค้ดสั้นกว่ามาก

## วิธีทดสอบ

- **โจทย์ 10 ข้อ** (profile, รายชื่อผู้ใช้, สร้างผู้ใช้, แก้/ลบโพสต์, รายการโพสต์ที่มี draft, สั่งซื้อ, ดูคำสั่งซื้อ, login)
- **AI 3 รุ่น** (Claude Haiku, Sonnet, Opus) แต่ละรุ่นเขียนทั้ง 10 ข้อ ด้วย hyperflat และด้วย Hono + zod รวม 6 ชุดต่อรอบ
- แต่ละ AI ทำงานแยกกัน เห็นเฉพาะโฟลเดอร์ของตัวเอง, โจทย์ และเอกสาร ไม่เห็นเทสต์ รัน `npm run check` ได้ แต่ห้ามเปิด server หรือเขียนเทสต์เอง
- **รอบ 1 สเปกละเอียด** (`kit/TASKS.md`): ระบุ field, status code และกฎทุกข้อ
- **รอบ 2 สเปกสั้นแบบ PM เขียน** (`kit/TASKS-brief.md`): บอกแค่ว่าใครทำอะไรได้ ให้ AI ตัดสินใจรายละเอียดเอง
- **Hidden test**: รอบ 1 มี 91 ข้อ (ฟังก์ชัน 30, ความปลอดภัย 61) รอบ 2 มี 71 ข้อ (21 + 50) ครอบคลุม IDOR, mass assignment, ข้อมูลรั่ว (password hash, payment token), validation, ราคาฝั่ง server, การล็อกบัญชีเมื่อเดารหัสผ่าน, Content-Type
- รอบ 2 ตรวจ**ข้อมูลที่ถูกบันทึกจริงใน db** ด้วย ไม่ใช่แค่ดูว่า API ตอบอะไร
- ทุกข้อเปิด server ใหม่ (db สะอาด) และรันซ้ำ 3 รอบเพื่อยืนยันว่าผลคงที่

**ตรวจความถูกต้องของเทสต์เอง:** ทั้ง reference solution ของ hyperflat และ Hono ผ่าน 100% ทั้งสองรอบ (เทสต์ไม่ลำเอียงเข้าข้างเฟรมเวิร์กไหน) และ negative control (โค้ด Hono ที่ใส่ช่องโหว่ IDOR กับ mass assignment ไว้) ถูกจับได้ทุกข้อ

## ผลรายละเอียด

**รอบ 1: สเปกละเอียด** (ฟังก์ชัน + ความปลอดภัย)

| | hyperflat | Hono |
|---|---|---|
| Haiku | 30/30 + 61/61 | 30/30 + 60/61 |
| Sonnet | 30/30 + 61/61 | 30/30 + 60/61 |
| Opus | 30/30 + 61/61 | 30/30 + 60/61 |

ข้อที่ Hono ไม่ผ่าน (ทั้ง 3 รุ่นเหมือนกัน): `POST /users` ยอมรับ JSON ที่ส่งมาด้วย `Content-Type: text/plain` เพราะ AI ทั้ง 3 รุ่น**ไม่ใช้ zod เลย** แล้วเรียก `c.req.json()` ตรงๆ ซึ่ง parse ทุก Content-Type ความเสี่ยงจริงในโจทย์นี้ต่ำ เพราะใช้ Bearer token ที่เบราว์เซอร์ไม่แนบให้อัตโนมัติ แต่ถ้าแอปใช้ cookie จะกลายเป็นช่อง CSRF ได้ (request แบบ `text/plain` ส่งข้ามเว็บได้โดยไม่ต้อง preflight)

**รอบ 2: สเปกสั้น**

| | hyperflat | Hono |
|---|---|---|
| Haiku | 21/21 + 50/50 | 21/21 + 50/50 |
| Sonnet | 21/21 + 50/50 | 21/21 + 50/50 |
| Opus | 21/21 + 50/50 | 21/21 + 50/50 |

AI ทุกรุ่นตัดสินใจเรื่องความปลอดภัยได้ถูกเองแม้สเปกไม่ได้บอก (ซ่อน password hash, กัน IDOR, ไม่รับ quantity ติดลบ, ล็อกบัญชีเมื่อเดารหัสผ่าน) มีผลแกว่ง 1 ครั้งจาก 18 รอบ ซึ่งรันซ้ำ 15 ครั้งผ่านทุกครั้ง จึงเป็นปัญหาของ harness ไม่ใช่โค้ด

**ขนาดโค้ด** (บรรทัดที่ไม่ว่างและไม่ใช่ comment, ทั้ง 10 โจทย์)

| | รอบ 1 hyperflat / Hono | รอบ 2 hyperflat / Hono |
|---|---|---|
| Haiku | 184 / 324 (1.8x) | 243 / 345 (1.4x) |
| Sonnet | 140 / 348 (2.5x) | 163 / 543 (3.3x) |
| Opus | 165 / 459 (2.8x) | 278 / 644 (2.3x) |

ใน Hono, AI มักเขียน validation และ auth เองทีละ route (ใช้ zod เพียง 10 จาก 60 ไฟล์) ซึ่งทำงานถูกต้อง แต่โค้ดยาว และแต่ละ route ตรวจไม่เหมือนกัน ทำให้ดูแลและ review ยากขึ้น

**Build check**
- AI ทั้ง 6 ชุดผ่าน `npm run check` ตั้งแต่ครั้งแรกเกือบทุกโปรเจกต์ (มีครั้งเดียวที่ Haiku รัน check ก่อนสร้างไฟล์) **จึงยังวัดไม่ได้ว่า error message ช่วยให้ AI แก้เองได้ดีแค่ไหน** เพราะ AI ไม่ทำผิดตั้งแต่แรก
- Mutation test (`tools/mutate.mjs`): นำ route ที่ AI เขียนทั้งหมด (66 route) มาลบหรือพิมพ์การประกาศ auth/schema ผิด แล้วดูว่า check จับได้ไหม
  - ลบ auth, ลบ response, ลบ params/body/query schema, พิมพ์ชื่อ option ผิด: **จับได้ 324/324 (100%)**
  - เปลี่ยน auth เป็น `'public'`: จับได้ 36/45 จับได้เมื่อ handler อ่าน `c.user` แต่ถ้าไม่อ่าน static check แยกไม่ได้ว่าตั้งใจหรือพลาด เพราะ `'public'` เป็นค่าที่ถูกต้องตามไวยากรณ์ สิ่งที่ check ช่วยได้คือแสดงระดับ auth ของทุก route ให้คน review

## ข้อจำกัด (สำคัญ)

- **โจทย์เล็กมาก** (1–2 route ต่อโปรเจกต์, ไม่มีโค้ดเดิม) ในแอปจริงที่มีหลายร้อย route, context ยาว, ทีมหลายคน หรือแก้โค้ดเดิม ความผิดพลาดน่าจะเกิดมากกว่านี้ และเป็นจุดที่ build check กับ response schema น่าจะมีค่าจริง แต่ PoC นี้ยังไม่ได้พิสูจน์
- **ใช้แค่ AI ตระกูลเดียว** (Claude) ยังไม่ได้ทดสอบ GPT, Gemini หรือโมเดล open-source ที่เล็กกว่า
- รอบละ 1 ครั้งต่อชุด (n=1) ผลที่ต่างกันเล็กน้อยอาจเกิดจากความสุ่มของโมเดล
- ใช้ JavaScript ล้วน ยังไม่ได้วัดผลของ TypeScript type-check
- เฟรมเวิร์กใน PoC นี้เป็นเวอร์ชันตีความ (interpreted) ที่มีพฤติกรรมเดียวกับ compiler ใน PoC 2 แต่ไม่ใช่ตัวเดียวกัน
- ผู้ออกแบบเฟรมเวิร์กกับผู้เขียนเทสต์เป็นคนเดียวกัน ป้องกันความลำเอียงด้วย reference solution ของ Hono ที่ผ่าน 100% แต่ควรให้คนอื่นเขียนโจทย์เพิ่ม

## ข้อเสนอสำหรับรอบถัดไป

1. โจทย์ขนาดใหญ่: แอปเดียว 30–50 route ที่มีโค้ดเดิมอยู่แล้ว และให้ AI "เพิ่มฟีเจอร์" แทนการเขียนใหม่
2. เพิ่มโมเดลอื่นและโมเดลขนาดเล็ก, รันซ้ำ 3–5 ครั้งต่อชุด
3. วัดเวลาและจำนวน token ที่ AI ใช้ (เบื้องต้นพบว่าใกล้เคียงกัน)

## โครงสร้างไฟล์

- `hyperflat/` — เฟรมเวิร์ก (schema, route, build check, server)
- `kit/` — สิ่งที่ AI ได้รับ: `TASKS.md` (รอบ 1), `TASKS-brief.md` (รอบ 2), `HYPERFLAT.md` (เอกสาร), `db.js`
- `runs/` — โค้ดที่ AI เขียน: `hyper-*`/`hono-*` รอบ 1, `b-hyper-*`/`b-hono-*` รอบ 2
- `logs/` — บันทึกทุกครั้งที่ AI รัน `npm run check`
- `hidden/` — hidden tests (`tests.mjs` รอบ 1, `tests2.mjs` รอบ 2) และตัวรันเทสต์
- `reference/` — reference solution ทั้งสองเฟรมเวิร์ก (ใช้ยืนยันว่าเทสต์ถูก)
- `results/` — ผลคะแนนแบบละเอียดทุกข้อ
- `tools/` — สร้าง workspace, `check`, mutation test

## รันเอง

```bash
npm install
node hidden/score.mjs runs/hyper-opus hyper                           # รอบ 1
TESTS=./tests2.mjs node hidden/score.mjs runs/b-hono-opus hono         # รอบ 2
node tools/mutate.mjs runs/hyper-haiku runs/hyper-sonnet runs/hyper-opus
```
